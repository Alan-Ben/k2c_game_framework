# 组队活动模块完整说明

## 一、模块概述

### 1.1 业务背景

组队活动模块为活动提供组队功能支持，允许玩家在活动中创建队伍、加入队伍、协同完成任务。通过组队玩法增强玩家社交互动，提升活动参与度和玩家粘性。

### 1.2 目标用户

- **社交型玩家**：喜欢与朋友一起游戏的玩家
- **活动参与者**：参与需要组队的活动玩家
- **公会成员**：公会组织的集体活动参与者

### 1.3 核心价值

1. **社交增强**：促进玩家间社交互动
2. **协同合作**：多人协作完成活动目标
3. **活跃提升**：组队提高活动参与意愿
4. **跨服互动**：支持跨服组队扩大社交圈

## 二、功能清单

### 2.1 队伍管理功能

| 功能名称 | 功能描述 | 用户价值 |
|---------|---------|---------|
| 创建队伍 | 创建新的活动队伍 | 成为队长管理队伍 |
| 解散队伍 | 队长解散队伍 | 结束队伍活动 |
| 退出队伍 | 成员退出当前队伍 | 离开不合适的队伍 |
| 队伍设置 | 修改队伍名称、宣言等 | 个性化队伍展示 |

### 2.2 成员管理功能

| 功能名称 | 功能描述 | 用户价值 |
|---------|---------|---------|
| 加入队伍 | 通过不同方式加入队伍 | 参与组队活动 |
| 踢出成员 | 队长移除队伍成员 | 管理队伍成员 |
| 申请审批 | 审核加入申请 | 控制队伍质量 |
| 成员列表 | 查看队伍所有成员 | 了解队伍情况 |

### 2.3 加入方式功能

| 功能名称 | 功能描述 | 用户价值 |
|---------|---------|---------|
| 自由加入 | 符合条件直接加入 | 快速组队 |
| 申请加入 | 需队长审批后加入 | 筛选成员 |
| 邀请加入 | 队长邀请后加入 | 定向邀请 |

### 2.4 条件设置功能

| 功能名称 | 功能描述 | 用户价值 |
|---------|---------|---------|
| 等级限制 | 设置最低/最高等级要求 | 筛选合适玩家 |
| 战力限制 | 设置最低战力要求 | 保证队伍实力 |
| 自动拒绝 | 不满足条件自动拒绝 | 提高管理效率 |

## 三、业务流程详解

### 3.1 创建队伍流程

```mermaid
flowchart TD
    A[玩家请求创建队伍] --> B{检查是否已在队伍}
    B -->|已在队伍| C[返回已在队伍错误]
    B -->|未在队伍| D{检查活动有效性}
    D -->|无效| E[返回活动无效错误]
    D -->|有效| F[验证创建参数]
    F --> G[创建队伍数据]
    G --> H[设置玩家为队长]
    H --> I[加入队伍成员列表]
    I --> J[推送创建成功通知]
    J --> K[返回队伍信息]
```

**详细步骤说明**：

1. **前置校验**
   - 检查玩家是否已在队伍中
   - 检查活动是否存在且有效
   - 验证队伍名称、宣言等参数

2. **队伍创建**
   - 生成唯一队伍ID
   - 设置队伍基础信息
   - 创建者为队长

3. **数据同步**
   - 保存队伍数据
   - 推送创建通知

### 3.2 加入队伍流程

```mermaid
flowchart TD
    A[玩家请求加入队伍] --> B{检查是否已在队伍}
    B -->|已在队伍| C[返回已在队伍错误]
    B -->|未在队伍| D{获取队伍信息}
    D -->|队伍不存在| E[返回队伍不存在错误]
    D -->|队伍存在| F{检查队伍是否已满}
    F -->|已满| G[返回队伍已满错误]
    F -->|未满| H{检查加入方式}
    H -->|自由加入| I[检查加入条件]
    H -->|申请加入| J[创建申请记录]
    H -->|邀请加入| K[检查邀请有效性]
    I -->|满足| L[加入队伍]
    I -->|不满足| M[返回条件不足]
    J --> N[通知队长审批]
    K -->|有效| L
    K -->|无效| O[返回无邀请]
    L --> P[广播成员加入]
```

**详细步骤说明**：

1. **条件检查**
   - 验证玩家是否已在队伍
   - 验证队伍是否存在
   - 验证队伍是否已满

2. **加入处理**
   - 自由加入：检查条件直接加入
   - 申请加入：创建申请等待审批
   - 邀请加入：验证邀请后加入

3. **加入成功**
   - 更新队伍成员列表
   - 广播成员加入通知

### 3.3 申请审批流程

```mermaid
flowchart TD
    A[队长查看申请列表] --> B[显示待审批申请]
    B --> C{选择操作}
    C -->|同意| D{检查队伍是否已满}
    D -->|已满| E[提示队伍已满]
    D -->|未满| F[检查申请者条件]
    F -->|不满足| G[自动拒绝]
    F -->|满足| H[同意加入]
    H --> I[移除申请记录]
    I --> J[加入队伍成员]
    J --> K[通知申请者]
    C -->|拒绝| L[移除申请记录]
    L --> M[通知申请者]
```

### 3.4 踢出成员流程

```mermaid
flowchart TD
    A[队长请求踢出成员] --> B{检查操作者权限}
    B -->|非队长| C[返回权限不足]
    B -->|是队长| D{检查被踢者是否在队伍}
    D -->|不在队伍| E[返回成员不存在]
    D -->|在队伍| F{检查是否踢自己}
    F -->|是| G[返回操作错误]
    F -->|否| H[移除成员数据]
    H --> I[广播成员移除通知]
    I --> J[通知被踢玩家]
```

### 3.5 退出队伍流程

```mermaid
flowchart TD
    A[玩家请求退出队伍] --> B{检查是否在队伍中}
    B -->|不在| C[返回不在队伍]
    B -->|在队伍| D{检查是否为队长}
    D -->|是队长| E{检查队伍人数}
    E -->|仅队长| F[解散队伍]
    E -->|有其他成员| G[转移队长给其他人]
    G --> H[退出队伍]
    D -->|否| H
    F --> I[广播解散通知]
    H --> J[广播退出通知]
    J --> K[返回成功]
```

## 四、关键规则

### 4.1 队伍规则

1. **队伍人数**
   - 最小人数：1人（队长）
   - 最大人数：根据活动配置，通常为5人

2. **队伍状态**
   - 开放中：可继续加入新成员
   - 已满：无法继续加入

3. **队伍有效期**
   - 活动期间有效
   - 活动结束自动解散

### 4.2 成员规则

1. **队长权限**
   - 修改队伍设置
   - 踢出成员
   - 审批申请
   - 解散队伍

2. **成员权限**
   - 查看队伍信息
   - 退出队伍
   - 查看申请列表（如有权限）

3. **队长转移**
   - 队长退出时自动转移
   - 转移给最早加入的成员

### 4.3 加入条件规则

1. **等级条件**
   - 最低等级限制
   - 最高等级限制（可选）

2. **战力条件**
   - 最低战力限制
   - 用于筛选实力玩家

3. **其他条件**
   - VIP等级
   - 公会成员

### 4.4 申请规则

1. **申请有效期**
   - 申请创建后24小时有效
   - 超时自动失效

2. **申请数量限制**
   - 每个队伍最多100条待处理申请
   - 超出后自动拒绝新申请
