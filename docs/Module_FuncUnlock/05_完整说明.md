# 功能解锁模块完整说明

## 一、模块概述

### 1.1 业务背景

功能解锁模块是 K2C 游戏的引导系统核心组件，负责管理游戏内各功能模块的逐步开放。通过合理的解锁条件设计，引导玩家循序渐进地体验游戏内容，避免新玩家面对过多功能时产生困惑，同时为玩家提供明确的成长目标。

### 1.2 目标用户

- **新玩家**：通过逐步解锁功能，降低游戏入门门槛
- **活跃玩家**：通过解锁条件获得持续的游戏目标
- **运营人员**：通过解锁配置控制游戏节奏和内容开放

### 1.3 核心价值

1. **游戏引导**：控制功能开放节奏，引导玩家逐步深入游戏
2. **目标驱动**：为玩家提供明确的短期目标
3. **体验优化**：避免信息过载，提升新手体验
4. **数据驱动**：通过解锁条件分析玩家行为

## 三、业务流程详解

### 3.1 功能解锁检查流程

```mermaid
flowchart TD
    A[玩家触发功能访问] --> B{检查功能解锁状态}
    B -->|已解锁| C[正常进入功能]
    B -->|未解锁| D{检查解锁条件}

    D -->|等级条件| E{当前等级 >= 解锁等级}
    D -->|任务条件| F{任务是否完成}
    D -->|章节条件| G{章节是否通过}
    D -->|组合条件| H{检查所有条件}

    E -->|满足| I[更新解锁状态]
    E -->|不满足| J[显示解锁条件提示]

    F -->|满足| I
    F -->|不满足| J

    G -->|满足| I
    G -->|不满足| J

    H -->|全部满足| I
    H -->|部分满足| J

    I --> K[推送解锁通知]
    K --> C

    J --> L[显示解锁进度]
    L --> M[显示条件描述]

    style C fill:#e8f5e9
    style I fill:#e3f2fd
    style J fill:#fff3e0
```

**详细步骤说明**：

1. **状态检查**
   - 查询功能解锁状态缓存
   - 未缓存时从配置计算解锁状态

2. **条件判定**
   - 等级条件：玩家当前等级 >= 配置解锁等级
   - 任务条件：指定任务状态为已完成
   - 章节条件：指定章节已通关
   - 组合条件：所有子条件同时满足

3. **状态更新**
   - 标记功能为已解锁
   - 记录解锁时间
   - 推送解锁通知

### 3.2 新功能解锁推送流程

```mermaid
flowchart TD
    A[玩家等级提升/任务完成] --> B{检查关联功能}
    B --> C[获取关联该条件的功能列表]
    C --> D{遍历功能列表}
    D --> E{功能是否已解锁}
    E -->|已解锁| F[跳过]
    E -->|未解锁| G{是否满足解锁条件}
    G -->|满足| H[更新解锁状态]
    G -->|不满足| F
    H --> I[生成解锁通知]
    I --> J[推送解锁消息]
    J --> K{还有更多功能}
    K -->|是| D
    K -->|否| L[结束流程]
    F --> K
```

**详细步骤说明**：

1. **事件监听**
   - 监听玩家等级变化事件
   - 监听任务完成事件
   - 监听章节通关事件

2. **关联查询**
   - 查询以该条件为解锁条件的功能列表
   - 按优先级排序

3. **批量解锁**
   - 遍历所有关联功能
   - 检查是否满足解锁条件
   - 批量更新解锁状态
   - 推送解锁通知

## 四、关键规则

### 4.1 解锁条件规则

1. **等级条件**
   - 玩家等级达到指定值时解锁
   - 最常用的解锁条件
   - 默认解锁等级为1级

2. **任务条件**
   - 完成指定主线任务后解锁
   - 任务必须为主线任务
   - 支持多个任务组合

3. **章节条件**
   - 通过指定章节后解锁
   - 章节进度必须完全通关
   - 支持多章节条件

4. **组合条件**
   - 多个条件同时满足时解锁
   - 条件之间为AND关系
   - 最多支持5个条件组合

### 4.2 功能类型规则

| 类型ID | 类型名 | 说明 | 典型功能 |
|--------|--------|------|----------|
| 1 | SYSTEM | 系统功能 | 背包、阵容、邮件、设置 |
| 2 | BUILDING | 建筑功能 | 客栈、铁匠铺、炼丹房、商铺 |
| 3 | ACTIVITY | 活动功能 | 精英副本、限时活动、竞技场 |
| 4 | SOCIAL | 社交功能 | 好友、公会、组队、聊天 |
| 5 | SHOP | 商店功能 | 商城、兑换、充值、神秘商店 |

### 4.3 解锁显示规则

1. **入口显示**
   - 未解锁功能入口显示锁定图标
   - 显示解锁条件简要描述
   - 点击显示详细解锁条件

2. **红点规则**
   - 新解锁功能显示红点提示
   - 红点持续到玩家首次点击
   - 红点可配置显示时长

### 5.1 新玩家故事

> 作为一名新玩家，我刚进入游戏时只能看到基础功能。随着等级提升，每升几级就会解锁新功能，系统会提示"恭喜解锁xxx功能"，让我对升级充满期待。当我到达10级时，公会系统解锁了，我迫不及待地加入了好友的公会，开始了社交玩法。

**关键触点**：
- 登录游戏 → 显示当前可解锁功能
- 达到解锁条件 → 弹窗通知解锁
- 点击解锁功能 → 进入新功能引导

> 作为一名活跃玩家，我一直在努力推进主线任务。当完成第5章后，精英副本功能解锁了，我可以挑战更高难度的副本获取稀有装备。解锁条件清晰显示在功能入口，让我知道下一步该做什么。

**关键触点**：
- 完成任务/章节 → 检查关联功能解锁
- 查看功能入口 → 显示解锁进度
- 完成所有条件 → 批量解锁通知

> 作为一名回归玩家，我看到很多新功能被锁定。通过查看解锁条件，我了解到需要先完成前置内容才能体验。系统逐步引导我补齐进度，让我不会感到迷茫。

**关键触点**：
- 登录游戏 → 全量检查当前状态
- 查看未解锁功能 → 显示完成进度
- 完成前置条件 → 解锁后续功能

## 七、客户端实现示例

### 7.1 功能入口显示

```csharp
/// <summary>
/// 功能入口UI组件
/// </summary>
public class FuncEntranceUI : MonoBehaviour
{
    [SerializeField] private int funcId;
    [SerializeField] private Image iconImage;
    [SerializeField] private Image lockIcon;
    [SerializeField] private Text nameText;
    [SerializeField] private Text conditionText;
    [SerializeField] private Button enterButton;
    [SerializeField] private GameObject redDot;

    private void Start()
    {
        RefreshUI();
    }

    private void OnEnable()
    {
        FuncUnlockManager.Instance.OnFuncUnlocked += OnFuncUnlocked;
        RefreshUI();
    }

    private void OnDisable()
    {
        FuncUnlockManager.Instance.OnFuncUnlocked -= OnFuncUnlocked;
    }

    private void RefreshUI()
    {
        var funcRef = GRefdataCoreMgr.instance.funcUnlockMap.getRef(funcId);
        if (funcRef == null) return;

        nameText.text = funcRef.funcName;

        bool isUnlocked = FuncUnlockManager.Instance.IsFuncUnlocked(funcId);

        if (isUnlocked)
        {
            // 已解锁状态
            lockIcon.SetActive(false);
            conditionText.gameObject.SetActive(false);
            enterButton.interactable = true;
            iconImage.color = Color.white;

            // 红点检查
            redDot.SetActive(FuncUnlockManager.Instance.HasNewUnlock(funcId));
        }
        else
        {
            // 未解锁状态
            lockIcon.SetActive(true);
            conditionText.gameObject.SetActive(true);
            conditionText.text = FuncUnlockManager.Instance.GetUnlockConditionDesc(funcId);
            enterButton.interactable = false;
            iconImage.color = Color.gray;
            redDot.SetActive(false);
        }
    }

    private void OnFuncUnlocked(int unlockedFuncId)
    {
        if (unlockedFuncId == funcId)
        {
            RefreshUI();
            PlayUnlockAnimation();
        }
    }

    public void OnClick()
    {
        if (FuncUnlockManager.Instance.IsFuncUnlocked(funcId))
        {
            // 清除红点
            FuncUnlockManager.Instance.MarkAsViewed(funcId);
            redDot.SetActive(false);

            // 进入功能
            EnterFunc();
        }
        else
        {
            // 显示解锁条件详情
            ShowUnlockDetail();
        }
    }

    private void ShowUnlockDetail()
    {
        var progress = FuncUnlockManager.Instance.GetUnlockProgress(funcId);
        UIManager.Instance.OpenWindow<UnlockDetailWindow>(win =>
        {
            win.SetData(funcId, progress);
        });
    }
}
```

### 7.2 解锁通知弹窗

```csharp
/// <summary>
/// 解锁通知管理器
/// </summary>
public class UnlockNotificationManager : MonoBehaviour
{
    [SerializeField] private GameObject notificationPrefab;

    private Queue<FuncUnlockInfo> _notificationQueue = new Queue<FuncUnlockInfo>();
    private bool _isShowing = false;

    /// <summary>
    /// 添加解锁通知
    /// </summary>
    public void AddNotification(FuncUnlockInfo info)
    {
        _notificationQueue.Enqueue(info);

        if (!_isShowing)
        {
            ShowNextNotification();
        }
    }

    /// <summary>
    /// 批量添加通知
    /// </summary>
    public void AddNotifications(List<FuncUnlockInfo> infos)
    {
        foreach (var info in infos)
        {
            _notificationQueue.Enqueue(info);
        }

        if (!_isShowing && _notificationQueue.Count > 0)
        {
            ShowNextNotification();
        }
    }

    private void ShowNextNotification()
    {
        if (_notificationQueue.Count == 0)
        {
            _isShowing = false;
            return;
        }

        _isShowing = true;
        var info = _notificationQueue.Dequeue();

        var go = Instantiate(notificationPrefab, transform);
        var window = go.GetComponent<FuncUnlockNotificationWindow>();
        window.SetData(info);
        window.OnClose = () =>
        {
            ShowNextNotification();
        };
    }
}
```

## 九、常见问题

### Q1: 为什么功能解锁状态不保存到服务端？

A: 功能解锁状态完全由客户端根据玩家数据（等级、任务、章节）实时计算，不需要单独存储。这样可以：
- 减少数据同步复杂度
- 避免数据不一致问题
- 降低服务端存储压力

### Q2: 如果玩家条件满足但未触发解锁怎么办？

A: 检查以下几点：
1. 是否正确监听了数据变更事件
2. 配置表中的条件是否正确设置
3. 是否存在前置依赖未满足

### Q3: 如何处理配置热更新？

A: 配置更新后，客户端会重新加载配置，并全量检查所有功能的解锁状态。
