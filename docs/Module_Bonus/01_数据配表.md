# Bonus 奖励系统模块 - 数据配表文档

## 模块概述

**模块名称**: Bonus (奖励系统)
**模块类型**: 客户端独立组件
**主要功能**: 提供奖励展示、奖励计算、奖励合并等通用奖励处理功能

## 1. 奖励信息节点 (BonusInfoNode)

### 完整字段列表

| 字段名 | 类型 | 必填 | 默认值 | 说明 | 约束条件 |
|--------|------|------|--------|------|----------|
| bonusId | int | 是 | - | 奖励ID，唯一标识 | 唯一，> 0 |
| bonusType | int | 是 | - | 奖励类型 | 1-5，对应枚举 |

| 4 | SKIN | SKIN | 皮肤类奖励 | skin_{id} |
| 5 | TITLE | TITLE | 称号类奖励 | title_{id} |

#### quality 品质等级

| 品质ID | 品质名称 | 颜色代码 | 排序权重 |

## 配表校验规则

### 奖励信息节点校验

| 字段名 | 校验规则 | 异常处理 | 校验时机 |
|--------|----------|----------|----------|
| bonusId | 必须唯一，范围 > 0 | 解析时跳过重复项 | 解析时 |
| bonusType | 范围 1-5 | 使用默认类型1 | 解析时 |
| resourceId | 必须关联有效配置 | 跳过无效奖励 | 解析时 |
| count | 必须 >= 1 | 设置为1 | 解析时 |
| quality | 范围 1-6 | 设置为1 | 解析时 |

### 校验流程图

```mermaid
flowchart TD
    A[解析奖励数据] --> B{数据格式检查}
    B -->|格式错误| C[记录日志，返回空]
    B -->|格式正确| D[遍历奖励列表]

    D --> E{bonusType有效?}
    E -->|否| F[使用默认类型]
    E -->|是| G{resourceId有效?}

    F --> G
    G -->|否| H[跳过该奖励]
    G -->|是| I{count有效?}

    H --> J{还有下一项?}
    I -->|否| K[设置count=1]
    I -->|是| L{quality有效?}

    K --> L
    L -->|否| M[设置quality=1]
    L -->|是| N[创建BonusInfoNode]

    M --> N
    N --> J

    J -->|是| D
    J -->|否| O[返回节点列表]

    style A fill:#e3f2fd
```

### 校验代码示例

```csharp
/// <summary>
/// 校验奖励信息节点
/// </summary>
public bool ValidateBonusInfoNode(BonusInfoNode node)
{
    if (node == null) return false;

    // 校验bonusId
    if (node.bonusId <= 0)
    {
        Debug.LogWarning($"无效的bonusId: {node.bonusId}");
        return false;
    }

    // 校验bonusType
    if (node.bonusType < 1 || node.bonusType > 5)
    {
        Debug.LogWarning($"无效的bonusType: {node.bonusType}, 使用默认值1");
        node.bonusType = 1;
    }

    // 校验resourceId
    if (node.resourceId <= 0)
    {
        Debug.LogWarning($"无效的resourceId: {node.resourceId}");
        return false;
    }

    // 校验count
    if (node.count < 1)
    {
        Debug.LogWarning($"无效的count: {node.count}, 设置为1");
        node.count = 1;
    }

    // 校验quality
    if (node.quality < 1 || node.quality > 6)
    {
        Debug.LogWarning($"无效的quality: {node.quality}, 设置为1");
        node.quality = 1;
    }

    return true;
}
```

```csharp
    var config = GRefdataCoreMgr.instance.getBonusTypeConfig(bonusType);

/// <summary>

public Color GetQualityColor(int quality)
{
    var config = GRefdataCoreMgr.instance.getQualityConfig(quality);
    if (config != null && ColorUtility.TryParseHtmlString(config.colorHex, out Color color))
    {
        return color;
    }
    return Color.white;
}
```

## 奖励合并计算公式

### 合并条件判断

```
可合并 = (类型相同) AND (资源ID相同) AND (配置允许合并)
```

### 合并后属性计算

```
合并后数量 = Σ(相同ID奖励的数量)
合并后品质 = max(相同ID奖励的品质)
```

### 合并示例计算

```
原始列表:
  - bonusType=2, resourceId=10001, count=5, quality=2
  - bonusType=2, resourceId=10001, count=3, quality=3
  - bonusType=2, resourceId=10001, count=2, quality=1

合并后:
  - bonusType=2, resourceId=10001, count=10, quality=3
```

### 合并流程图

```mermaid
flowchart TD
    A[获取奖励列表] --> B[按类型+ID分组]
    B --> C[遍历每个分组]
    C --> D{分组数量 > 1?}

    D -->|是| E[累加count]
    D -->|否| F[保持原样]

    E --> G[取最大quality]
    F --> H[添加到结果列表]
    G --> H

    H --> I{还有下一分组?}
    I -->|是| C
    I -->|否| J[返回合并后列表]

    style A fill:#e3f2fd
    style J fill:#c8e6c9
```

## 配置加载流程

```mermaid
sequenceDiagram
    participant Client as 客户端
    participant ResMgr as 资源管理器
    participant Cache as 内存缓存

    Client->>ResMgr: 加载 BonusTypeConfig
    ResMgr->>ResMgr: 解析类型配置
    ResMgr->>Cache: 缓存类型映射

    Client->>ResMgr: 加载 QualityConfig
    ResMgr->>ResMgr: 解析品质配置
    ResMgr->>Cache: 缓存品质映射

    Client->>ResMgr: 加载 BonusDisplayConfig
    ResMgr->>ResMgr: 解析展示配置
    ResMgr->>Cache: 缓存展示参数

    ResMgr-->>Client: 配表加载完成
```
