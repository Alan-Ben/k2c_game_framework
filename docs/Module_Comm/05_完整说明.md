# 通用操作模块完整说明

## 一、模块概述

### 1.1 业务背景

通用操作模块是 K2C 游戏的核心功能模块，包含招募、抽卡、红点系统、阶段目标、问卷调查等多种通用功能。该模块集中管理游戏中的通用玩法，为其他模块提供基础支持。

### 1.2 目标用户

- **所有游戏玩家**：通过招募和抽卡获取角色和道具
- **运营人员**：通过问卷收集玩家反馈
- **系统管理员**：管理红点和阶段目标配置

### 1.3 核心价值

1. **资源获取**：招募和抽卡系统是玩家获取稀有资源的主要途径
2. **用户引导**：阶段目标引导玩家游戏进程
3. **信息提醒**：红点系统帮助玩家及时了解游戏动态
4. **用户调研**：问卷系统收集玩家反馈

## 三、业务流程详解

### 3.1 招募流程

```mermaid
flowchart TD
    A[请求招募] --> B{获取招募配置}
    B -->|配置不存在| C[返回配置错误]
    B -->|存在| D{检查次数限制}
    D -->|已达上限| E[返回次数已用完]
    D -->|未达上限| F{检查消耗资源}
    F -->|资源不足| G[返回资源不足]
    F -->|资源充足| H[扣除消耗资源]
    H --> I[执行招募随机]
    I --> J{检查保底}
    J -->|触发保底| K[发放保底奖励]
    J -->|未触发| L[发放随机奖励]
    K --> M[更新招募数据]
    L --> M
    M --> N[推送获得物品]
    N --> O[返回招募结果]
```

**详细步骤说明**：

1. **配置验证**
   - 获取招募配置信息
   - 验证招募池是否开放

2. **条件检查**
   - 检查每日次数限制
   - 检查资源是否充足

3. **执行招募**
   - 扣除消耗资源
   - 判断是否触发保底
   - 随机抽取奖励

4. **奖励发放**
   - 发放抽到的奖励
   - 更新招募统计

### 3.2 抽卡流程

```mermaid
flowchart TD
    A[请求抽卡] --> B{获取抽卡配置}
    B -->|配置不存在| C[返回配置错误]
    B -->|已结束| D[返回活动已结束]
    B -->|进行中| E{检查抽卡次数}
    E -->|无效次数| F[返回次数错误]
    E -->|有效| G{检查消耗资源}
    G -->|资源不足| H[返回资源不足]
    G -->|资源充足| I[扣除消耗资源]
    I --> J[执行抽卡随机]
    J --> K{检查保底}
    K -->|触发保底| L[发放保底奖励]
    K -->|未触发| M[发放随机奖励]
    L --> N[更新抽卡数据]
    M --> N
    N --> O[更新累计次数]
    O --> P[推送获得物品]
    P --> Q[返回抽卡结果]
```

**详细步骤说明**：

1. **配置验证**
   - 获取抽卡池配置
   - 验证抽卡池是否开放

2. **次数检查**
   - 抽卡次数只能为1或10
   - 检查十连是否有折扣

3. **保底处理**
   - 检查当前保底计数
   - 达到保底次数时触发保底

4. **累计奖励**
   - 更新累计抽卡次数
   - 检查是否达成累计奖励

### 3.3 红点刷新流程

```mermaid
flowchart TD
    A[红点刷新触发] --> B[获取红点配置]
    B --> C[计算红点数量]
    C --> D{数量是否变化}
    D -->|无变化| E[不推送]
    D -->|有变化| F[推送红点变化]
    F --> G{是否有父红点}
    G -->|有| H[递归刷新父红点]
    G -->|无| I[结束]
    H --> I
```

**详细步骤说明**：

1. **触发刷新**
   - 模块状态变化触发
   - 定时刷新触发

2. **数量计算**
   - 根据配置计算红点数量
   - 如邮件未读数、任务可领取数等

3. **层级刷新**
   - 红点支持层级关系
   - 父红点数量为子红点之和

### 3.4 阶段目标流程

```mermaid
flowchart TD
    A[查看阶段目标] --> B{检查目标完成状态}
    B --> C{检查子任务}
    C -->|未完成| D[显示进度]
    C -->|全部完成| E{检查是否领取}
    E -->|未领取| F[显示可领取]
    E -->|已领取| G[显示已完成]
    F --> H[点击领取]
    H --> I[发放奖励]
    I --> J[更新目标状态]
    J --> K[推送变化通知]
```

### 3.5 问卷流程

```mermaid
flowchart TD
    A[请求问卷信息] --> B{检查问卷存在}
    B -->|不存在| C[返回问卷不存在]
    B -->|存在| D{检查问卷时间}
    D -->|未开始/已结束| E[返回问卷不可用]
    D -->|进行中| F{检查是否已完成}
    F -->|已完成| G[返回已完成状态]
    F -->|未完成| H[返回问卷内容]
    H --> I[玩家答题]
    I --> J[提交答案]
    J --> K{验证答案完整性}
    K -->|不完整| L[返回答案不完整]
    K -->|完整| M[发放问卷奖励]
    M --> N[记录完成状态]
```

## 四、关键规则

### 4.1 招募类型规则

| 招募类型 | 类型ID | 说明 |
|----------|--------|------|
| 普通招募 | 1 | 基础货币招募 |
| 英雄招募 | 2 | 钻石招募英雄 |
| 伴侣招募 | 3 | 招募伴侣 |
| 特殊招募 | 4 | 限时招募 |

### 4.2 抽卡类型规则

| 抽卡类型 | 类型ID | 说明 |
|----------|--------|------|
| 普通抽卡 | 1 | 基础奖池 |
| 限定抽卡 | 2 | 限时UP池 |
| 友情抽卡 | 3 | 友情点抽卡 |

### 4.3 保底规则

1. **小保底**：累计一定次数必得SR以上
2. **大保底**：累计更多次数必得SSR
3. **保底继承**：同一池子的保底计数继承

### 4.4 红点层级规则

1. **父子关系**：红点可配置父子关系
2. **数量汇总**：父红点数量为所有子红点之和
3. **状态同步**：子红点清除时，父红点自动更新
