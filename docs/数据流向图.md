# K2C 游戏框架 - 数据流向图

## 一、概述

本文档描述 K2C 游戏框架中数据在各模块间的流转过程，包括数据输入、处理、存储和输出的完整链路。

---

## 二、数据流总览

### 2.1 整体数据流向

```mermaid
flowchart TB
    subgraph 客户端["客户端层"]
        UI[UI界面]
        Comp[组件管理器]
        Cache[本地缓存]
    end

    subgraph 网络层["网络传输层"]
        Proto[协议封装]
        Net[网络连接]
    end

    subgraph 服务端["服务端处理层"]
        Handler[协议处理器]
        Logic[业务逻辑]
        Event[事件系统]
    end

    subgraph 存储层["数据存储层"]
        CacheSrv[服务端缓存]
        DB[(数据库)]
    end

    UI --> Comp
    Comp --> Proto
    Proto --> Net
    Net --> Handler
    Handler --> Logic
    Logic --> Event
    Event --> CacheSrv
    CacheSrv --> DB

    DB --> CacheSrv
    CacheSrv --> Logic
    Logic --> Handler
    Handler --> Net
    Net --> Proto
    Proto --> Comp
    Comp --> Cache
    Cache --> UI
```

### 2.2 数据流层次说明

| 层次 | 职责 | 数据形态 |
|------|------|----------|
| **客户端层** | 用户交互、数据展示 | UI数据、本地缓存 |
| **网络传输层** | 数据序列化、网络传输 | 协议消息 |
| **服务端处理层** | 业务逻辑处理 | 业务对象 |
| **数据存储层** | 数据持久化 | 数据库记录 |

## 九、数据流向总结

### 9.1 数据流向统计

| 数据类型 | 主要来源 | 主要去向 | 存储位置 |
|----------|----------|----------|----------|
| 玩家数据 | 登录、行为 | 展示、排行 | player表 |
| 物品数据 | 奖励、购买 | 使用、出售 | player_bag_item表 |
| 英雄数据 | 招募、培养 | 战斗、驻扎 | player_hero表 |
| 任务数据 | 行为触发 | 奖励发放 | player_quest表 |
| 公会数据 | 创建、加入 | 社交、活动 | guild表 |
| 货币数据 | 充值、奖励 | 消费、兑换 | player_resource表 |

### 9.2 关键数据流特点

1. **实时性要求高**：战斗数据、聊天消息需要实时同步
2. **一致性要求高**：货币、物品数据需要严格一致性保护
3. **批量处理优化**：任务进度、成就统计采用批量处理
4. **缓存策略重要**：频繁访问数据采用多级缓存
